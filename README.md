# 光影调参 ShotTuner

拍照教练：实时分析取景画面，把 ISO、快门、色温该拨到哪一档告诉你，同时在取景器上教构图。**它不负责拍照——拍照用你自己的相机。**

## 它解决什么问题

手机相机全自动模式在四类场景下经常翻车：

| 场景 | 自动模式的问题 | 本应用的策略 |
|---|---|---|
| 夜景 | 死命拉高 ISO，噪点糊成一片 | 优先放慢快门，把 ISO 压在噪点可接受区间 |
| 逆光 | 平均测光把画面拉亮，天空直接曝废 | 检测高光截断，主动压曝光保高光 |
| 人像 | 快门偏慢，轻微手抖就虚 | 上调快门下限，冻结主体微动 |
| 室内暖光 | 越拍越黄，白平衡漂移 | 灰世界估算残余色偏，给出色温修正值 |

## 三种工作模式

- **教练模式（默认）**：只读画面做分析，把建议值显示在屏幕上，你切到原生相机专业模式照着拨。
- **本机写入（可选）**：通过 Camera2 的 `SENSOR_SENSITIVITY` / `SENSOR_EXPOSURE_TIME` 真正改参数，闭环收敛。适合验证算法，不适合当主力拍摄方式。
- **构图教练**：三分线、水平基准、主体交点标记，见下文。

## 悬浮教练（实验性）：在系统相机上给建议

按「悬浮卡」按钮 → 允许「显示在其他应用上层」→ 再点一次 → 确认录屏 → 应用自动退到后台 → 打开小米相机，屏幕上方会出现一张卡，显示场景、`ISO · 快门 · 色温`、一句构图建议。卡可拖动，点「停」关闭。

实现路径是 **MediaProjection 录屏 + TYPE_APPLICATION_OVERLAY 浮窗**，分析的是屏幕上的相机预览画面。这是「在系统相机上给建议」唯一可行的技术路径，但有三条硬约束：

1. **只读不写**。录屏拿到的是像素，不是相机会话。建议仍然要你自己去专业模式拨。
2. **有延迟**。录屏帧率受系统限制（5–15fps），画面到建议差 100–300ms，快速摇镜时明显滞后。适合「站稳了再调」，不适合追拍。
3. **要授权**。Android 14 起每次启动都需重新确认录屏，通知栏常驻一条提示，这是系统强制。

工程上的两个关键处理：浮窗必须带 `FLAG_SECURE`，否则自己的卡会被自己的录屏采进画面，下一帧就把建议文字当成场景内容；分析时裁掉画面上下边缘（12%–88%），避开相机 App 的模式栏和快门按钮对测光的污染。

**未在真机验证。** 部分 ROM 会把相机预览渲染到受保护图层上，导致录屏里该区域全黑；出现这种情况时卡片数值会停在初始值不动。

v1.4 起悬浮卡一次给三行：照片三参数、录像方案（分辨率/帧率/快门）、一条当前该做或别做的功能建议。

## 四页：照片 / 录像 / 功能 / 技法

参数只是拍照的一部分，所以主界面拆成四页，各答一个问题：

| 页 | 回答的问题 | 内容 |
|---|---|---|
| 照片 | 这三个数拨多少 | ISO / 快门 / 色温 / 偏差，构图分与构图建议，直方图 |
| 录像 | 这场怎么录 | 八种拍摄意图 → 分辨率、帧率、快门、码率、防抖、LOG、对焦、收音 |
| 功能 | 该不该换模式 | 弱光该开夜景、逆光该开 HDR、弱光别用长焦、拍人该切几倍 |
| 技法 | 这一手怎么拍 | 39 条场景技法，按当前画面挑最该注意的 3 条，点开是完整动作分解 |

技法页不是电子书。`knowledge/` 下是一套**可匹配的知识层**：每条技法带触发条件（场景、亮度、高光截断、肤色占比、边缘密度、是否有长焦、能否手动曝光），`TechniqueMatcher` 用「场景 +40 分、每个数值条件 +8 分、硬件条件不满足直接出局、同分类最多一条」选出三条，保证三张卡从不同角度看同一个画面，而不是把一句话说三遍。

每条技法固定六段：什么时候用 / 怎么做（3-5 步具体动作）/ 为什么（讲光学或视觉原理，不写「这样更好看」）/ 常见错误 / 起手参数（吸到拨盘档位）/ 拍完怎么验。分类覆盖人像、风光、夜景、食物、街头、宠物小孩、微距、剪影、用光、室内弱光、基本功。

知识层刻意不依赖 Android：`knowledge/` 下零 `android.*` import，所以能在 JVM 单元测试里直接跑，6 组断言卡住条目数、文案长度、分类覆盖和三条典型画面的匹配结果。

录像页的核心不是给个「4K 60」，而是**180 度快门**：快门时间必须是帧间隔的一半，24fps→1/48、30fps→1/60、60fps→1/120。违反这条，运动物体会出现频闪和抖动感。想让画面变暗应该加 ND 减光镜，而不是拨快门——这是手机用户最容易搞错的一点。

功能页的规则都挂在可测特征上，没有「AI 猜你喜欢」：

- 弱光 + 静止 → 建议手持夜景（多帧合成降噪）
- 弱光 + 运动 → **禁止**夜景（合成需要静止，一动就糊），改专业模式高快门
- 长焦传感器面积 < 主摄 50% 且画面偏暗 → 劝退长焦，宁可主摄裁切
- 高光溢出 > 4% → 建议 HDR 或压曝光
- 主摄等效焦距 18–28mm 且检出人脸 → 建议切 2 倍，避免广角变形

## 覆盖所有机型：不查机型表，直接问系统要真值

「支持市面上所有机型」如果靠维护机型白名单，一定会过期——同型号不同固件、不同地区版本的能力都不一样。本应用的做法是**运行时探测**：

| 探测项 | 来源 | 用途 |
|---|---|---|
| ISO 范围、快门范围 | `SENSOR_INFO_SENSITIVITY_RANGE` / `SENSOR_INFO_EXPOSURE_TIME_RANGE` | 把建议值钳制在硬件能做到的范围内 |
| 等效焦距 | 物理焦距 × 43.267 ÷ 传感器对角线 | 算手持安全快门（1/等效焦距），不查表 |
| 各分辨率实际帧率 | `getOutputMinFrameDuration` | 4K 能不能 60、1080P 能不能 120 |
| 慢动作最高帧率 | `getHighSpeedVideoFpsRangesFor` | 决定慢放倍数 |
| 防抖、10bit、RAW、多摄 | `LENS_INFO_AVAILABLE_OPTICAL_STABILIZATION` 等 | 推荐是否可用 |

机型名只用于显示，参数一律走探测值。品牌（小米/华为/OPPO/vivo/荣耀/三星/Pixel…）只影响一件事：**这个按钮在你的手机上藏在哪**——`BrandGuide` 按品牌给出专业模式、电影模式、慢动作、参考线的入口路径，因为菜单名各家不同且会随版本变，文案里统一附「找不到就在设置里搜关键词」。

## 端侧 AI：自己带模型，不依赖厂商助手

手机自带的 AI 助手（小爱、小艺、小布）**没有向第三方开放「识别当前画面」的能力**，系统级视觉入口只服务自家相机和相册，也没有标准 API。所以这里走的是自带模型：

- **ML Kit Face Detection**：判断有没有脸、几张、占多大面积。这是判人像最硬的证据——肤色规则会被暖墙、木桌骗，人脸检测不会。
- **ML Kit Image Labeling**：400+ 通用标签（Sky / Mountain / Beach / Food / Dog…），判断风景、食物、宠物、建筑。

模型打包进 APK，离线运行，不依赖 Google 服务，因此对所有 Android 机型成立。代价是安装包 +12MB 左右。

融合原则按证据强度排，不是「谁先进听谁的」：

1. 检出人脸（面积 ≥ 1.2%）→ 直接判人像，无条件覆盖规则；
2. 打标置信度 ≥ 0.85，或规则自己拿不准（< 0.60）→ 采用 AI 改判；
3. 逆光是例外：规则用「P95 极高 + P05 极低 + 动态范围大」判，这个组合比打标可靠，AI 说风景也不改。

界面上的场景标签会注明来源：`人像 92% · AI·人脸`。AI 用的是 160×120 的降采样图（每帧顺手存下颜色，几乎不增加开销），够判大类，不做面部细节。


## 照着拨：建议值都吸附到了拨盘档位

这是「教练」能不能用的关键细节。推荐值不会给出 `1/63` 这种数——它会被吸附到快门拨盘上真实存在的档位（`1/60`），ISO 同理吸附到 1/3 档序列。宁可差 1/3 档，也不能让用户在列表里找不到可以选的数。

小米专业模式（14 Pro 实测口径）：

| 拨盘 | 含义 | 建议值的来源 |
|---|---|---|
| ISO | 感光度 | 场景噪声容忍 × 快门余量分配后的结果 |
| S | 快门，1/60 表示 1/60 秒 | 先受手抖极限与主体运动约束，再让 ISO 补曝光 |
| WB | 色温 2000–10000K | 灰世界色偏反推，混合光下建议锁死 |
| EV | 曝光偏移 | 手动模式下失效，本应用的「偏差」是画面亮了/暗了几档，不是要你拨的 EV |


## 技术栈

- Android 原生，Kotlin，minSdk 24（Android 7.0）
- CameraX 1.3.4 + Camera2Interop（手动曝光必须走 Camera2 通道）
- 无第三方图像库，YUV 平面直读，单帧分析 < 6ms
- Python 侧为等价算法参考实现，用于快速迭代与回归验证

## 构建

前提：JDK 17、Android SDK（platform 34、build-tools 34.0.0）。

```bash
# 方式一：Android Studio 直接打开 shottuner/ 目录，Build → Build APK
# 方式二：命令行
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

安装到手机：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

首次启动需要授予相机权限。设备若不支持 `CONTROL_AE_MODE_OFF`，应用会自动降级为纯推荐模式。

## 算法核心

曝光量 `E = ISO × 快门时间`。调参的本质是把 `E` 调到让平均亮度落到场景理想值，再在 ISO 与快门之间做约束分配。

```
EV 偏差 = log2(目标亮度 / 实测亮度)
        - 高光保护项（溢出越多压得越狠）
        + 暗部抬升项（死黑面积大时补亮，逆光场景不补）
分配：先定快门（受手持下限与场景上限约束），ISO 补足剩余曝光量
      若 ISO 触顶仍不够亮 → 判定为光线不足，提示补光或上脚架
```

三条硬约束决定"建议值是否真的能执行"：快门不能慢于手抖极限、不能快于场景需求、ISO 不能超过噪声容忍度。
另外最终 ISO 会吸附到相机的 1/3 档位序列——「ISO 72」这种值在真机上根本设不了。

闭环控制依赖一个关键事实：**必须知道当前画面是用什么参数拍出来的**。实现方式是在 `CaptureResult` 里读取每一帧的 `SENSOR_SENSITIVITY` 与 `SENSOR_EXPOSURE_TIME`。没有这个反馈，冷启动只能盲猜，必然过冲。

## 构图教练

取景器上叠一层引导，三个元素对应三条构图原则：

- **三分线**：九宫格 + 四个交点。交点是最容易把主体放稳的位置，比「放中间」有张力，比「随手放」有秩序。
- **水平参考线 + 实际地平线**：绿色短线是「平」的基准，橙色虚线是画面里真实的地平线（结构张量估出来的倾角）。两条线重合就是水平，不用读数字。
- **主体标记 + 目标交点**：青色圆圈是算法认定的视觉重心，白色虚线圈是最近的三分交点，中间那条虚线就是「该往哪挪」。

诊断输出两件事：构图分（0–100）和最多两条人话建议（带原因，比如「地平线横在正中间会显得呆板」——教的是判断，不是命令）。

主体显著性用「局部对比度 + 肤色权重」近似，配合两条否决规则避免乱指挥：

1. **长条区域不算主体**。地平线、栏杆、书架竖线会让显著性掩膜变成一条细线，直接判为「结构」而不是「主体」，否则任何一张有地平线的照片都会被建议挪主体。
2. **散布太广不算主体**。噪声和满屏纹理会让显著块撒满画面，此时输出「画面元素比较散，先选一个主体」而不是编一个交点。

倾角估计的已知偏差：块均值降采样会把阶梯状边界估得略陡，实测系统性偏大约 15%（8° 报 9.6°）。这个偏差对「转手机对齐水平线」的动作没有影响，但不要拿它做测量工具。

```bash
cd python
python -m pip install numpy pillow pytest

```

合成样张的判定与建议结果：

| 样张 | 判定 | 置信度 | 建议 |
|---|---|---|---|
| outdoor.jpg（晴天风景） | 风景 | 63% | ISO 80 · 1/500 |
| night.jpg（夜晚街景） | 夜景 / 弱光 | 63% | ISO 1600 · 1/8（提示上脚架） |
| backlit.jpg（逆光窗边） | 逆光 | 65% | ISO 100 · 1/500 |

## 已知边界

1. **白平衡只给建议，不写入**。手动 R/G/B 增益在不同厂商机型上差异极大，强行写入容易偏色甚至导致会话崩溃。这是有意的保守取舍。
2. **iOS 不支持**。iOS 第三方应用无法自由控制快门与 ISO 的连续值，只能走 `AVCaptureDevice` 的有限区间，产品形态需要重做。
3. **微信小程序做不到**。小程序 `camera` 组件只暴露 zoom / flash / 前后摄，没有任何曝光参数入口。
4. **自动写入会有轻微闪屏**。CameraX 的 CaptureRequest 在 UseCase 构建时固定，改参数必须重建用例，已通过 1.2 秒节流 + 变化阈值把影响降到最低。
5. **无法接管系统相机**。Android 的相机是独占资源，第三方应用既不能向系统相机的会话里写参数，也不能在系统相机前台时自动弹起自己。想「打开原生相机就有人帮我调」，只能走录屏采集 + 悬浮窗的形态：读得到画面，写不进参数，还有约 100ms 延迟。本应用选择的是「自带取景器」这条路——参数能写真，构图引导零延迟，代价是拍照要在本应用里按快门。
6. **构图引导不认语义**。它判断的是「视觉重心」，不是「一只猫」。画面里有多个同等强度的元素时，给出的交点建议可能不是你想拍的那个，此时关掉网格自己来更可靠。
