# L1 · JVM-only 用法（commonMain / commonTest 里绝不能出现）
# ─────────────────────────────────────────────────────────────────────────────
# 消费者：tools/ci/check-common-purity.sh（秒级本地自查）
# 权威检查：CI 的 :shared:compileCommonMainKotlinMetadata（metadata 编译只允许 common API）
#
# ★ 为什么必须有这一档：
#   Android 有 javaClass、java.text.SimpleDateFormat、java.lang.Math、ThreadLocal …
#   **commonMain 里用了它们，Android 侧编译是绿的，iOS 上直接编译失败。**
#   真实发生过（两次）：
#     ① ScoreHistory 用了 `t.javaClass.simpleName` —— Android 编译一路绿灯，
#        是 CI 的 metadata 编译把它抓出来的。若没有那道门禁，
#        这个 bug 要等到**第一次真机出包**才暴露 —— 那时整个编译周期已经浪费了。
#     ② commonTest 里的 `java.util.Locale` —— **Android 编译也一路绿灯**
#        （commonTest 只在 JVM 上编），但 iOS 侧编 commonTest 时直接失败。
#        这次是**人**发现的，不是机器 → 所以扫描范围扩到了 commonTest，
#        而且特征串补齐了 `Math.round` / `.format(` 这两个当时漏掉的形态。
#   这个 bug 要等到**第一次真机出包**才暴露 —— 那时整个编译周期已经浪费了。
#
# ★ 本清单**只是快速反馈，不完备**：没被模式覆盖的 API、签名/类型差异都抓不到。
#   所以 CI 里两道都在。
#
# ★ 纪律：特征串只放在清单里，脚本不写字面量。
#
# 固定字符串匹配（grep -F），一行一条，'#' 之后为注释。
# ★ 大小写敏感 —— 这条很重要：`Math.round`（java.lang，JVM-only）
#   与 `kotlin.math.round`（common API）是两个东西，只差首字母大小写。

# ★ 为什么要补：T07 收尾时 commonTest 里的 `java.util.Locale` 是**人**发现的。
#   复盘发现，就算当时把 Locale 挑出来，同一批文件里的
#   `Math.round(...)` 与 `"%.1f".format(...)` 这两个形态**特征串也抓不到**
#   —— 清单里有 `java.lang.Math` 和 `String.format`，但代码里写的是
#   简写 `Math.round` 与扩展函数形式 `"...".format(...)`。
#   ⇒ 门禁只抓到了"我碰巧写的那一种形态"，等于没抓。
#   所以这里把**实际会出现在代码里的写法**都列上。
