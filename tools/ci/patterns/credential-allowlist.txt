# G1-d · 按「路径::特征串」精确豁免
# ─────────────────────────────────────────────────────────────────────────────
# 格式：<仓库相对路径>::<特征串>     一行一条，'#' 之后为注释。
#
# ★ 为什么不用"排除 docs/**"这种目录级排除？
#   目录级排除 = 在 docs/ 里贴真密钥也能过。承诺式豁免不是豁免。
#   本文件把豁免精确到「某一个文件的某一个特征串」：
#     · 同一个文件里出现**另一个**新特征串 → 仍然红（豁免不会自动扩大）；
#     · 严格档（PEM 私钥、.p8 文件、非空签名身份）→ 不在豁免范围内，永远红；
#     · 每条豁免都在 git 里，PR diff 看得见 → 属于"可审计的承诺"，不是隐藏。
#
# ★ 纪律：豁免只允许用于"文档为了说明门禁而引用特征串"这一种理由。
#   任何"我确实需要在这里写凭据"的想法都必须走别的路（secrets / 本机不外传）。
#
# ★ 语法说明：特征串里的 ':' 需按原样写；路径相对仓库根，不带前导 './'。
# ── 文档为了说明门禁本身而引用特征串 ─────────────────────────────────────────
# 这份文档在讲「怎么写这道门禁」，里面必然出现被禁词本身。
# 按纪律：豁免必须精确到「某一个文件的某一个特征串」——
# 同一个文件里出现**另一个**新特征串仍然会红，豁免不会自动扩大。
# 严格档（真私钥形态）不在豁免范围内，永远红。
