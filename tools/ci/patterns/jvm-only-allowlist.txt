# L1 · JVM-only 用法的精确豁免（按「路径::特征串」）
# ─────────────────────────────────────────────────────────────────────────────
# 消费者：tools/ci/check-common-purity.sh
# 格式：<仓库相对路径>::<特征串>     一行一条，'#' 之后为注释。
#
# ★ 什么时候需要豁免？
#   扫描范围是 commonMain **和** commonTest 两个源集。
#   commonTest 里将来可能有**合法**的 JVM-only 用法 —— 比如某个测试
#   就是要验证 JVM 行为（"在 JVM 上 String.format 应该是 X"）。
#   这类用例不能删，那就给它一条精确豁免。
#
# ★ 为什么不用目录级排除？
#   目录级排除 = 在 commonTest/ 里塞真 JVM-only 代码也能过。承诺式豁免不是豁免。
#   本文件把豁免精确到「某一个文件的某一个特征串」：
#     · 同一个文件里出现**另一个**新特征串 → 仍然红（豁免不会自动扩大）；
#     · 每条豁免都在 git 里，PR diff 看得见 → 属于"可审计的承诺"，不是隐藏。
#
# ★ 语法说明：特征串里的 ':' 需按原样写；路径相对仓库根，不带前导 './'。
#
# ★ 纪律：豁免只允许用于"这个测试就是要验证 JVM 行为"这一种理由。
#   "我懒得改"不是理由 —— 那说明该用例属于 app 侧，不该放 commonTest。
#
# ── 当前无豁免 ────────────────────────────────────────────────────────────────
# （T07 收尾时 commonTest 里的 java.util.Locale / Math.round / .format(
#   是通过**把用例搬到 app 侧**解决的，不是靠豁免。
#   豁免清单留空是好事：每一条都是一笔明账。）
