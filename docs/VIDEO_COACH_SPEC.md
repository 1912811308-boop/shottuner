## 0. 一句话结论

现有 App 已经解决了「参数该拨到几」和「三分线对不对」。视频里真正缺的三件事是：

1. **手机该放多高、什么角度**（蹲拍、美食 45°、运镜用腰不用手）；
2. **人像取景的几何规则**（脸在中心、脚在底边、别切关节、别放边缘）；
3. **时机**（夜景的蓝调时刻、逆光的补光顺序）。

这三件事都能用现有传感器和 `FrameStats` 做出来，不需要新模型，也不需要新权限（蓝调时刻除外，定位可选）。

## 2. 可落地的技巧清单

### T01 全身人像：蹲下来拍，脸在中心，脚在底边

- 出处：BV1Qf4y1h7h7 01:22–01:45
- 原话要点：男生站着俯拍会把女生拍矮；正确做法是蹲下，手机高度在腰部以下，人脸放画面中心附近，脚放画面底部。
- 判定信号：`AiVisionResult` 已有 `faceCount` / `faceArea`，需补人脸中心 `faceCenterX/Y` 与人像外框（可由 `skinGrid` 求包围盒）。
- App 动作：
  - 人脸中心 `y < 0.38` → 「手机举太高了。蹲下，把镜头降到腰以下」；
  - 人物外框底边 `y < 0.88` → 「退半步，把脚留在画面底部，腿才显长」；
  - 人脸中心 `y` 在 0.42–0.58 且底边 > 0.90 → 「这个机位对了」。
- 验收：合成人像样张，脸中心 0.25 时出第一条；0.50 + 底边 0.95 时出确认语。

### T02 广角透视：脸别贴边，脚可以贴边

- 出处：BV1Qf4y1h7h7 02:10–03:00
- 原话要点：1× 主摄等效 24mm，边缘会拉长物体；把人脸放边缘会变形，把腿放边缘反而显长。
- 判定信号：`faceCenterX < 0.18 || > 0.82`，且当前为 1× 主摄（`DeviceProfile.equivFocalMm in 18..28`）。
- App 动作：「人脸太靠边会被拉宽，往中间挪一点；腿可以留在边上」。
- 验收：faceCenterX=0.1 触发，0.5 不触发。

### T03 半身用 2×，全身用 1×

- 出处：BV1Qf4y1h7h7 05:12–05:45；BV1vv411c7FD 00:34
- 原话要点：2×（等效约 50mm）最接近人眼，不产生明显透视变形，半身人像优先用它。
- 判定信号：`faceArea > 0.06`（半身/特写）且 `equivFocalMm in 18..28`。
- App 动作：建议切 2×；若 `faceArea > 0.18`（特写）建议 2×/3× 而非凑近。
- 注意：`FeatureAdvisor` 第 7 条已有「拍人切 2 倍」，本条是把触发条件从「有肤色」收紧到「人脸够大」，避免全身照也被建议切 2×。

### T04 别切关节

- 出处：BV1Qf4y1h7h7 00:57
- 原话要点：构图时乱切身体关节（脖子、腰、膝盖、脚踝）看起来难受。
- 判定信号：人像外框底边落在 `0.44–0.52`（腰）或 `0.62–0.72`（膝）附近。
- App 动作：「取景别切在腰/膝盖上，往上或往下挪半格」。
- 验收：底边 0.48 触发腰提示，0.67 触发膝提示，0.55 不触发。

### T05 构图模式：留白与填充

- 出处：BV1Q64y1T7ox 04:20–04:45；BV1vv411c7FD 02:35–02:55
- 原话要点：主体占比小 + 环境好 = 留白构图（安静、孤独）；主体塞满画面 = 填充构图（强注意力）。
- 判定信号：`CompositionHint.subjectSize`（已有）与 `edgeDensity`。
- App 动作：
  - `subjectSize < 0.10 && edgeDensity < 0.18` → 「留白构图：人再小一点，让环境占 2/3」；
  - `subjectSize > 0.55` → 现有文案「退一步」改为二选一：「想拍特写就再靠近让局部充满画面；想拍环境就退一步」。

### T06 人像朝向决定放哪条三分线

- 出处：BV1Q64y1T7ox 02:06–02:12
- 原话要点：人朝右就放左三分线，人朝左就放右三分线，否则像「面壁思过」。
- 判定信号：ML Kit `Face` 的 `headEulerAngleY`（正=朝右）绝对值 > 15°。
- App 动作：人脸朝右且 `subjectX` 在右侧 → 「他朝右看，把人放到左三分线，视线才有去处」。
- 验收：eulerY=+25°、subjectX=0.7 触发；eulerY=0 不触发。

### T07 美食三个角度

- 出处：BV1xb411C7Z2 02:17–02:57
- 原话要点：平视拍汉堡这类有层次的；45° 拍制作过程；90° 俯拍拍满桌菜。
- 判定信号：重力传感器俯仰角 `pitch` + `AiVisionResult.scene == FOOD`。
- App 动作：显示「当前 18° · 适合拍层次；拍满桌请抬到 90°」；偏离推荐角 >12° 才提示，避免唠叨。
- 验收：pitch 15/45/90 三档文案正确；判 FOOD 但 pitch 连续小抖动不闪文案（滞回 6°）。

### T08 美食用柔光，别用顶灯

- 出处：BV1xb411C7Z2 01:47–02:10
- 原话要点：同一份食物，室内普通光很普通，均匀柔光下立刻有食欲。
- 判定信号：`highlightClip > 0.04 && shadowClip > 0.20`（硬光高反差）。
- App 动作：「把盘子挪到窗边，让光从侧面来；关掉头顶直射的灯」。
- 归属：`FeatureAdvisor` 新增 FOOD 分支（`AiVisionResult.scene == FOOD` 时传入）。

### T09 夜景时机：蓝调时刻

- 出处：BV11V411H7D8 00:51–01:08
- 原话要点：太阳落山、天还没黑、天空发蓝的 20 分钟最好拍：城市灯亮着，暗部还有细节。
- 判定信号：`SceneType.NIGHT` + 当前时间 + 粗略经纬度。
- App 动作：卡片显示「蓝调时刻 17:51–18:02，还有 12 分钟」；不在窗口内显示「今天蓝调已过，明天 17:50」。
- 实现：本地太阳高度角（NOAA 简化公式），太阳高度 -6°～-4° 为蓝调。**不需要网络**。定位权限做成可选，拒绝时用系统时区中心点 + 允许手动选城市。
- 验收：北京 2026-10-17，日落 17:30，蓝调（太阳高度 -4°～-6°）17:51–18:02，误差 ≤ 3 分钟（用 Python 参考实现对照，见第 5 节）。

### T10 夜景长曝：低 ISO + 支撑 + 倒计时

- 出处：BV11V411H7D8 01:47–02:20
- 原话要点：ISO 压低、快门放慢，必须上三脚架；按快门那一下会抖，用倒计时或手表快门。
- 判定信号：`NIGHT` + 设备静止（加速度计 1.5 秒方差低于阈值）。
- App 动作：`needsTripod` 时补一句「用 2 秒倒计时按快门，或用手表/耳机音量键，别用手指戳」；静止且极暗时给 ISO 100 / 1–10s 的长曝方案。
- 验收：静止序列触发长曝卡；手持抖动序列只给常规夜景方案。

### T11 逆光：先点测光，再找反光面，最后转 45°

- 出处：BV1oRwmetEn9 00:23–02:38
- 原话要点：大光比下要么天空过曝要么主体欠曝；可用反光板、闪光灯、渐变镜、HDR、包围曝光，手机最实用的是 HDR + 补光 + 换角度。
- 判定信号：现有 `SceneType.BACKLIT`。
- App 动作：把现有 1 条扩成有顺序的 3 条：
  1. 点脸测光，曝光补偿 -0.7～-1.0（保高光）；
  2. 脸还是黑 → 让人面向最近的白墙/浅色地面/白纸，或穿浅色衣服；
  3. 都不行 → 转 45° 侧逆光，让太阳在画面外。
- 注意：不要建议开闪光灯直打（手机闪光灯指数低、色温硬），视频里的闪光灯方案是外接灯，手机场景不适用。

### T12 运镜：用腰不用手

- 出处：BV1jb4y1r7wu 00:50–03:05
- 原话要点：手持运镜放低重心、手臂夹紧、用腰胯发力；长距离平移走「太极步」；手机数码变焦掉画质，用走位代替变焦；摇镜头交代空间，甩镜头做无缝转场。
- 判定信号：`TYPE_GYROSCOPE` 角速度 + 线性加速度。
- App 动作：录像页增加「稳定度」条（0–100）：
  - 角速度 RMS > 0.35 rad/s → 「摇太快了，速度减半」；
  - 垂直加速度 RMS 高 → 「用腰和胯发力，手臂别伸太直」；
  - 平移中角速度持续 > 0.15 → 「走太极步：脚跟先着地，膝盖微屈」。
- 验收：注入三组模拟传感器序列（静止/慢摇/快甩），评分单调且提示对应。

### T13 专业模式补充卡

- 出处：BV1nW4y1J7Tx 00:41–04:40
- 要点：
  - 手动 ISO + 快门后 EV 失效（README 已写，界面要再说一次）；
  - 长按对焦框可锁 AE/AF，适合逆光、舞台、隔着玻璃；
  - RAW+ 是「一张亮 + 一张暗」机内合成，不是真 RAW 单帧，动态范围大但不能当 14bit 原始文件调；
  - 1×/2×/3.3× 是镜头切换，双指放大是裁切。
- App 动作：`FeatureAdvisor` 的 KNOW 卡补「长按锁 AE/AF」与「RAW+ 的真相」两条，各一句话。

## 4. 数据结构建议

```kotlin
/** 机位教练的一条结论。severity: 0=提示 1=建议 2=必须改 */
class FramingAdvice(
    val title: String,      // 「蹲下，手机降到腰以下」
    val reason: String,     // 「站着俯拍会把腿拍短，广角还会放大脸」
    val severity: Int
)

object FramingCoach {
    fun advise(
        face: FaceInfo?,          // AiVisionResult 里的人脸部分
        subject: SubjectBox?,     // 由 skinGrid 求的包围盒
        comp: CompositionHint,
        profile: DeviceProfile
    ): List<FramingAdvice>
}

/** 技巧卡：内容层，和规则解耦，方便以后从视频继续补 */
class TechniqueCard(
    val id: String,          // "T01"
    val category: String,    // 构图 / 人像 / 夜景 / 美食 / 录像
    val title: String,
    val action: String,      // 一句话怎么做
    val why: String,         // 为什么
    val check: String,       // 怎么判断自己做对了
    val sourceBvid: String   // 出处，空串表示通用摄影原理
)
```

`FramingCoach` 保持纯函数：不碰 Android API，输入是归一化坐标，方便在 `app/src/test` 里跑 JUnit。

## 5. 测试与验收

1. **Python 参考实现**：`python/shottuner/framing.py` 与 `astro.py`，与 Kotlin 同一套常数；`pytest` 至少覆盖：
   - 全身/半身/特写三档焦距建议；

   - 美食角度滞回：15→45→15 不来回闪。
2. **Kotlin 单测**：`app/src/test/java/.../FramingCoachTest.kt`，纯 JVM，不依赖 Robolectric。
3. **真机清单（小米 14 Pro）**：
   - 蹲拍全身：提示出现的时机是否早于用户按快门；
   - 美食 45°：转动手机时刻度是否跟手；
   - 夜景蓝调：定位授权/拒绝两条路径都能出结果；
   - 逆光：三条建议是否按顺序只显示当前最该做的那条。
4. **回归**：现有 24 个 pytest 必须全绿；四张合成样张的场景判定不得变化。

## 6. 明确不做

- 不做语义主体识别（CNN）：现有显著性 + 人脸足够覆盖教学场景，加模型会让包体和耗电上升。
- 不做机位推荐（地图/卫星图）：视频里的找机位方法依赖地图产品，不属于本 App 职责。
- 不做「工作日亮灯率」「天气」提醒：数据源不可靠，宁可不做。
- 不把姿态度数当测量仪器：只用于「蹲下/抬高/转到 45°」这类动作引导，误差 ±2° 可接受。
- 不在本迭代动 `ScreenCaptureService` 的浮窗链路：先保证取景器内闭环，浮窗复用同一套规则即可。
