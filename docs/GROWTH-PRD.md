> 版本目标：v3.1.0「能被口口相传」

> 最后更新：2026-10-20

## 0. 一页纸结论

**这不是"能不能上架"的问题，是"有没有人主动安利"的问题。**

v3.0.0 已经是一个**合规、可靠、能过审**的应用。但它现在有四个结构性短板，每一个都直接压死传播：

| # | 短板 | 证据（代码层） | 后果 |
|---|---|---|---|
| 1 | **没有"我变强了"的证据** | 拍完只弹一张 5 秒自动消失的复盘卡；分数不落盘（`MainActivity.buildShotReview()` 算完就丢） | 用户用一周也答不出"我进步了吗"→ 不留存 |
| 2 | **成片不带产品痕迹** | `saveShotToGallery()` 原图直写相册，无水印、无分享入口 | 用户发朋友圈 = 零曝光。这是最致命的一条 |
| 3 | **最强功能门槛最高** | 悬浮教练要过 4 道门：隐私 → 相机 → `SYSTEM_ALERT_WINDOW`（跳系统设置）→ `MediaProjection`（截屏弹窗） | 卖点还没被看见，人已经走了 |
| 4 | **首屏给参数不给结果** | 首屏主位是 `ISO 320 · 1/60 · WB 5600K` | 80% 的目标用户（拍照小白）看不懂 → 首屏即劝退 |

**爆款化的核心动作只有一句：把"拍完才知道好不好"改成"取景时就知道，并且能发出去炫"。**

零网络是硬约束（manifest 里 `INTERNET` 已被 `tools:node="remove"` 移除，这是隐私合规的立身之本，不能回退）。因此**所有常规增长手段（账号、云同步、推送、A/B、社区、线上素材）全部不可用**。能在零网络下跑的只有两根杠杆：

- **留存**：靠"每次使用都感到自己变强了"（本地进度 + 本地曲线）
- **传播**：靠"产物本身"（水印 + 对比卡 + 系统分享 Intent）

下面全部方案都建立在这两根杠杆上。

## 1. 竞品拆解

### 1.1 直接竞品：实时构图指导类

| 竞品 | 平台 | Aha 时刻 | 留存钩子 | 传播机制 | 对我们的启示 |
|---|---|---|---|---|---|
| **Camera51** | **仅 iOS** | 打开对准物体，立刻出"主体偏右，向左移动 15cm" | 构图框实时跟随，绿色=到位 | 无明显机制 | **安卓端这个位置是空的**（来源：微信公众号「织美」2026-03-12 实测文，明确写"只支持 iOS"）。这是我们的最大机会窗口 |
| 绘心相机 | Android | 拍摄时 AI 实时提示构图和动作 | 拍完上传照片获取灵感推荐 | 需联网 | 它的"拍完上传"恰好是我们的反面卖点 |
| 浅影 AI 相机 | Android | 实时取景 + AI 构图引导 + 姿势模板 | 从取景到修图全流程 | 需联网 | 功能铺得宽，反而没有记忆点 |
| Doka / Doka 相机 | Android | AR 引导找机位 + 滤镜 | 滤镜库 | 需联网 | 主打滤镜，不是教学 |

**结论**：安卓端"实时构图教练"这个品类**有竞品但没有赢家**，且全部依赖云端 AI。我们的差异化不是"更聪明"，而是**"离线、零延迟、不上传"** —— 这一点在隐私口碑上可以硬吃。

### 1.2 间接竞品：我们要抢的是它们的用户时间

| 竞品 | 品类 | 它解决什么 | 为什么不抢它的赛道 |
|---|---|---|---|
| 美图秀秀 / 醒图 / 无他相机 | 拍后美化 | 拍完变好看 | 打不过，且滤镜会稀释"教你拍"的定位 |
| Camera FV-5 / ProShot | 专业参数 | 手动控制相机 | 极客向，量小；我们的参数能力是配角 |
| VSCO / Snapseed | 后期 + 风格 | 调色 | 同上，且需要联网素材 |
| 轻颜 / Ulike | 美颜 + 姿势 | 自拍好看 | 人群重叠但不冲突，不值得改定位去抢 |

### 1.3 竞品没做、我们能做的三件事

1. **免拍照即可得分**：所有竞品的分数都在"拍完之后"。我们的 `ScoreBoard.score()` 本来就吃**实时取景统计量**（1 Hz），技术上**完全支持不按快门就出分**。这是把 Aha 提前 30 秒的钥匙，且竞品架构上做不到。
2. **零网络这个卖点本身**：竞品都在"上传照片"，我们在"不上传"。隐私觉醒的 2026 年，这是可以写进商店标题的话。
3. **技法图鉴（收集进度）**：83 条技法天然是一本可收集的册子。竞品的知识都是无限的流，我们是**有限可穷尽的** —— 有限才有达成感。

## 2. 定位候选（≤ 15 字）

| # | 定位句 | 字数 | 优点 | 风险 |
|---|---|---|---|---|
| A | **拍之前就知道好不好** | 9 | 直击痛点（拍完才发现废片），且与竞品的"拍后修"形成对立 | 略负向，像在恐吓 |
| B | **手机里的摄影陪练** | 8 | "陪练"暗示陪着你进步，可承载图鉴/打卡体系 | 不够直白，需副标题解释 |
| C | **教你把照片拍好，不是修好** | 11 | 定位清晰，把美图系划到对立面 | 字数偏长，商店标题放不下 |

**推荐：主标题 B + 副标题 A。**

- 商店标题：`光影调参 - 手机里的摄影陪练`
- 商店副标题/一句话简介：`拍之前就知道好不好 · 离线实时构图教练，照片不上传`
- 应用内首屏不动（"光影调参"品牌已定，不折腾）

理由：B 是"我们能长大成什么"（陪练 → 图鉴 → 打卡 → 成长曲线，一条完整的叙事线），A 是"用户现在为什么要下载"（钩子）。零网络下商店页是**唯一**的获客入口，标题必须同时完成这两件事。

## 3. Aha 时刻：最短路径

### 3.1 现状路径（估算，代码走查得出）

```
冷启动 ──▶ 隐私门（全屏模态，必须点同意）        ~5s
        ──▶ 相机权限系统弹窗                     ~3s
        ──▶ 取景，1Hz 分析出参数                 ~2s
        ──▶ 用户读到「ISO 320 · 1/60 · 5600K」   ← 小白无感 ✗
        ──▶ 必须自己按快门才拿到分数              ← 门槛 ✗
```

**问题**：在第 4 步，一个不懂 ISO 的用户获得的唯一反馈是一串他看不懂的数字。第 5 步要求他先付出"拍一张"的成本才能拿到奖励。**Aha 根本没发生。**

### 3.2 目标路径（≤ 30 秒，不依赖悬浮窗，不依赖网络，不要求拍照）

```
冷启动 ──▶ 权限合并一屏（隐私+相机+通知，一次说清）  ~4s
        ──▶ 取景器中央浮出「任务卡」：
            「把主体挪到右上交点」                    0s（立刻）
        ──▶ 三分线+目标交点高亮，主体靠近时环由灰转绿
        ──▶ 主体进入目标区 ──▶ 环变绿 + 15ms 震动 + 「到位」  ~5–15s
        ──▶ 立刻出「首张成绩卡」：
            「参考分 78 · 良好」
            「你刚才做对了：三分法」
            [再来一张]  [看图鉴]                      ≤30s ✓
```

**三个关键设计决定：**

1. **不拍照也能得分。** `ScoreBoard.score(stats, hint, roll, scene)` 的输入全是实时取景统计量，不需要 `ImageCapture`。这意味着 Aha 的成本从"拍一张"降到"挪一下手机"。这是全案最大的单点杠杆。
2. **任务卡只给一条，且必须是"可完成"的。** 从构图/水平/曝光里挑**当前画面最接近达标**的那一条（`ScoreBoard.buildRecommendations()` 已按扣分比例降序，取第一条即可），保证 5–15 秒能完成。任务太难 = 挫败，太易 = 无成就感。
3. **首屏层级重排**（参数降级，不删除）：
   - **L1（主位）**：一句话任务 + 到位反馈 + 参考分
   - **L2**：四维小条（水平/曝光/构图/清晰）
   - **L3（页签内，折叠）**：ISO / 快门 / WB —— 懂的人自己会找

   ⚠️ 参数能力**不能删**。它是 ProShot 那批用户留下的唯一理由，只是不该占首屏主位。

## 4. 传播机制（零网络可行）

排序按"单条影响力 × 实现成本"。

### 4.1 成绩水印 —— P0，最高优先

**做什么**：每张成片右下角烧一行半透明文字 + 小 logo。

```
                                    光影调参
                          参考分 78 · 良好 · 三分法
```

**为什么最高优先**：这是**唯一**能跟着用户照片跑出应用的东西。用户发朋友圈/小红书/群聊 = 免费广告位，且带的是"我拍得好"的正向社交货币，不是硬广。没有它，传播数恒等于 0。

**实现要点**：
- 在 `MainActivity.saveShotToGallery()` 里，`contentResolver.openOutputStream(uri)` 之前，把 `source` 解码 → Canvas 画水印 → 压缩写回。**原图不动**（缓存里的临时文件本就要删）。
- 水印位置按图片短边等比缩放，避免 4:3 和 16:9 下溢出。
- **默认开，设置里可关。** 强制加水印会被差评淹没；默认开才能拿到曝光。关掉的人已经用过几次了，损失有限。
- 分数未测全时（`allMeasured == false`）烧「参考分 --」，与 UI 口径一致，不烧假数字。

### 4.2 一键系统分享 —— P0

复盘卡上加「分享」按钮 → `FileProvider` + `ACTION_SEND`，把带水印的图交给微信/朋友圈/小红书/蓝牙。零网络、零新增权限。

需要新增：`res/xml/file_paths.xml` + `FileProvider` 声明（`<provider>` 在 manifest）。注意 `authorities` 必须用 `${applicationId}`，不能写死。

### 4.3 前后对比卡 —— P0（低成本版）/ P1（同场景版）

**低成本版（P0，与 G4 合并做）**：取本地历史里的「本周第一张」和「本周最高分那张」，左右拼图，中间写「+19 分」。

> 不需要同场景，不需要存原图（只存 48dp 缩略图，用现成的 `loadThumbBitmap()` 逻辑）。成本极低，传播力来自"我进步了"的叙事，而不是照片本身多好看。

**同场景版（P1）**：教练在建议变化时自动存一张低清缩略图当「听之前」，成片当「听之后」。更震撼，但需要额外缓存管理，放 P1。

### 4.4 挑战卡 —— P1

每周一个主题（"今天拍 3 张逆光人像"），完成生成一张方形卡片图可分享。零网络下主题只能本地预置（写死在代码里，12 周一轮）。不做动态下发。

## 5. 本地留存体系（零网络）

### 5.1 技法图鉴 —— P0，回来的理由

83 条技法（`TechniqueBookV15` 44 条 + `PhotographyBook` 39 条）做成一本可收集的册子。

- 首页入口显示「已解锁 12 / 83」+ 进度条
- 解锁条件：**照做一次**（例如构图任务"到位"一次，或拍出的照片该维度得分 ≥ 80%）
- 解锁时有一次轻动效 + 一句话解释"这条技法在什么时候用"
- 未解锁的显示灰色条目名（保留好奇心，但不剧透内容）

**为什么这是 P0**：收集进度是**零网络下唯一能制造"未完成感"的机制**。没有它，用户第二次打开没有任何理由。

### 5.2 分数曲线 —— P1，回答"我变强了吗"

每次拍照落盘一条 `(时间戳, 总分, 水平, 曝光, 构图, 清晰)`：

- 30 天折线图（自绘，不引图表库）
- 顶部一句话：`第 1 张 61 → 现在 79 · +18`
- 这直接补上 §0 短板 #1

**存储决策**：**不引入 Room / SQLDelight**。理由：(1) 新增依赖会冲击已调好的 R8 规则与包体；(2) 数据量极小（每人每天几十条，上限 500 条环形覆盖）；(3) 现有代码库零数据库依赖，引入会破坏"纯 JVM 可单测"的优势。
- 落盘：`filesDir/history.json`，`JSONObject` 手写，写入走后台线程
- 计数类（解锁位图、连续天数）：`SharedPreferences`（已有 `uiPrefs` 先例）

### 5.3 连续天数 —— P1

连续拍照天数。**必须与内容绑定**（"今天解锁了：逆光先对脸测光"），否则打卡本身没有价值，纯数字打卡在第 4 天就会崩。

| 现在 | 改成 |

| 4 道门：隐私 → 相机 → 悬浮窗（跳系统设置）→ 截屏授权 | 主界面先完成 Aha，悬浮窗作为「进阶玩法」入口，用户自愿来 |

| — | Quick Settings Tile（`CameraTileService` 已有）保留为一键拉起主界面的免额外权限入口 |

## 9. 明确不做（反向清单）

| 不做 | 为什么 |
|---|---|
| 账号 / 云同步 / 排行榜 | 需要网络，且与"照片不上传"的隐私卖点直接冲突 |
| 社区 / UGC / 评论 / 点赞 | 需要网络 + 审核成本，个人开发者扛不住 |
| 滤镜 / 美颜 / 贴纸 | 稀释"教你拍"的定位，且正面打不过美图系 |
| 教程视频流 | 包体爆炸，且零网络下无法更新内容 |
| 付费墙 / 订阅 | 爆款期先要量，付费墙会掐死传播 |
| 埋点 / 远程配置 / A/B | 无网络，做不了 |
| **无障碍** | **clover 明确要求不做**（48dp 热区、contentDescription、reduce motion 一律不加） |

### ⚠️ 必须让 clover 知道的一个结构性劣势

**零网络 = 零埋点 = 我们看不到任何真实使用数据。**

爆款迭代通常靠数据驱动（Aha 到达率、次日留存、分享率）。我们一个都拿不到。

应对：
1. **接受现实**，用可用性走查 + 真机自测替代数据（G1 的"30 秒出成绩"是可以人工掐表验证的）。
2. **看商店评论**——这是零网络下唯一的用户反馈渠道，上架后必须每天看。
3. G11 的本地统计只能给用户自己看，不能回传。

## 11. 风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 水印被用户反感打差评 | 中 | 高 | 默认开但设置可关；水印做小做淡（右下角、≤ 图片短边 4% 高） |

| 图鉴解锁判定误触发（刷分） | 低 | 低 | 解锁要求"照做 + 得分达标"双条件，且同一技法每天最多解锁 1 条 |

| 并发会话覆盖产物（另一会话也在改这棵树） | 中 | 高 | 每版出包后核对 `dist/` 里 APK 的时间戳与 versionCode |
